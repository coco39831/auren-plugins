# 人與 Agent 共用的插件開發守則

## 開始前先寫清楚

每個插件先回答：提供什麼能力、輸入是什麼、成功輸出是什麼、依賴哪些能力、需要哪些資料及權限、什麼情況必須失敗，以及如何證明完成。說明用途，不擅自替使用者增加人格、行為目標、提示詞或資料用途。

先搜尋已發布的能力契約。能符合既有契約就實作替代品；需要新語意才新增自己的命名空間。不直接匯入其他插件的內部模組或讀寫其資料庫表。

## 最短開發流程

以下在 Auren 專案根目錄執行，建立的是開發副本，不改動正式 Agent。

```powershell
.venv\Scripts\python.exe plugins/devkit.py new build/my-plugin --id local.my-plugin
```

1. 編輯 `plugin.json`：名稱、作者、授權、能力契約、執行環境及權限。
   每個出口另以 `name`、`description`、`features` 說明具體效果與特色，例如「跨對話的長期記憶」，而不是只讓使用者看到 `service`。說明只供介面呈現，不是模型提示詞；未能提供的效果不得寫成承諾。
2. 先寫 `schemas/input.json`、`schemas/output.json`，保持欄位少且含義明確。
3. 編輯 `src/main.py` 的能力函式；預設 stdio 範本保留 RPC 生命週期。其輸入是資料，不是宿主物件。需要同程序服務工廠時，改依下節工廠規約開發，不混用兩種入口。
4. 更新 `tests/cases.json`。必須有具體輸入及可驗證的預期輸出，至少涵蓋正常情境與空值或邊界情境。
5. 檢查、對可信程式試跑、再封裝：

```powershell
.venv\Scripts\python.exe plugins/devkit.py validate build/my-plugin
.venv\Scripts\python.exe plugins/devkit.py probe build/my-plugin --allow-native
.venv\Scripts\python.exe plugins/devkit.py pack build/my-plugin --output build/my-plugin-1.0.0.auren-plugin
```

靜態檢查不執行程式。`probe --allow-native` 是開發者明確同意執行可信本機程式，沒有隔離、完整程序樹限制或磁碟資源隔離，不能對來路不明的程式使用。此旗標不會替正式使用者授權，也不會把套件的 `brokered` 宣告變成已驗證的隔離能力。

目前 probe 支援 stdio Python 範本，實際呼叫初始化、案例及結束，驗證回應識別碼、輸出 Schema 與結果。它不建立工廠需要的 `NativeContext`，也不模擬已連上正式記憶庫、模型或平台權限；需這些依賴的整合測試必須另取得真實執行證據。

## 同程序服務工廠的開發流程

適用於需要承接本地 Service Protocol 的高信任 Python 服務；完整定義見 [factory 原生服務工廠規格](FORMAT.md#factory-原生服務工廠-v1)。

1. 清單明列 `runtime.kind=python`、`runtime.access=native`、`runtime.transport=factory` 與 `host.native` 權限。`runtime.kind=native` 的執行檔目前不是這種工廠入口。
2. 入口實作 `create(context, export_id)`，依出口識別碼回傳服務物件。不在模組匯入時啟動背景工作、改資料或呼叫外部模型。
3. `exports[].methods` 列出相容方法，宿主會檢查可呼叫性；不要把它當權限限制、逐方法的 JSON Schema 或資料隔離保證。
4. 公開 JSON 能力呼叫需實作 `invoke(arguments, context)`，並提供輸入／輸出 Schema。其他本地相容方法沿用其 Service Protocol，不以 ORM 實體或任意內部物件跨一般 JSON 入口傳遞。
5. 透過 `context.require(contract)` 取得需要的服務；在清單宣告需求，不匯入其他插件的私有實作。透過 `context.callback(name)` 使用宿主明列的建構回呼，不猜名稱、不把回呼寫到設定或磁碟，也不把暫時延續保留到其他任務。
6. `context.data_root` 是 Agent 的資料根，不是隔離區。新資料使用自己的子目錄；承接舊服務時保留原資料位置並驗證讀寫及回復。使用 `context.config` 讀取自己的設定，不能把 `context.options` 整份交給介面、stdio 或日誌。
7. 長工作呼叫 `context.checkpoint()`，尊重取消並提供資源清理。它只是合作式檢查，無法讓任意同程序原生操作變成可單獨強制中止的 worker。
8. 以真正的插件宿主測試建構、方法契約、依賴循環、版本及設定切換、公開 JSON 呼叫與資源結束。既有 stdio `probe` 不會建立 `NativeContext`；不能把靜態格式或假回覆當成工廠整合驗收。

工廠與宿主共用程序及記憶體，風險高於受控 worker：失敗可能影響整個 Auren，且方法列表不會阻止取得 Python 原生能力。必須把這件事寫在使用說明與權限理由中；不得宣稱它是沙箱。只有可信來源及已明確授權的版本才能載入。

官方封裝是完整性保護的發行資產，不直接修改其中的程式、提示詞或清單。要做替代品，建立自己的插件識別碼，實作相同契約，測試、打包新版本並切換能力綁定；不要讓安裝器覆蓋官方識別碼。自己已安裝的插件更新也應建立新版本，不就地編輯執行中的完整性快照。

## 共通規則

1. **只有一份真實格式**：清單及流程以 Schema 為準，README 描述要與程式一致；不要自訂另一套只靠文字解讀的欄位。
2. **不暗中降級**：必要能力不可用就清楚回報。重試及替代路徑須由工作流程明列，不能偷偷用模型先驗代替資料庫、假回覆代替工具。
3. **權限不等於宣告**：清單只提出需求；有效授權由宿主確認。Agent 不能藉由編輯自己的清單增加實際權限。
4. **不寫死環境**：不放開發機路徑、連接埠、帳戶、API 金鑰或硬體識別。使用相對套件路徑、宿主設定與秘密參照。
5. **人格及記憶有歸屬**：官方人格仍只允許成長與問模式塑形入口。跨 Agent 存取需要明確共享設定。插件移除不等於刪除記憶。
6. **提示詞可檢查**：提示詞放在獨立檔案，在 `prompts` 明列用途。必要的程式內嵌指令亦須在說明指明檔案與函式，不藏入通用錯誤訊息或模板。檔案清單不是能證明「絕無隱藏指令」的自動掃描器，仍需原始碼審查。
7. **資料最少化**：紀錄事件種類、相對程式位置與執行識別，不記錄使用者原文、私鑰、憑證、模型完整上下文或任意例外原文。
8. **外部資料不是命令**：網頁、文件與工具輸出不得自行變更插件綁定、授權或宿主規則。
9. **資源可清理**：回應取消、結束自己建立的子程序、關閉檔案及連線。不用背景常駐程序避開宿主停止要求。
10. **可更新也可恢復**：保持穩定識別碼，破壞變更提升契約主要版；搬移先備份，保留可驗證的回復程序。

## 不同種類怎麼寫

| 類型 | 開發重點 |
| --- | --- |
| 工具 | 一次呼叫完成一項明確操作；結果應包含可核對成果，不只一句「成功」 |
| 記憶／知識提供者 | 明確區別命中、空結果、錯誤；提供資料版本、匯出與搬移契約 |
| 思考插件 | 輸出供後續使用的計畫、證據要求或指引；不宣稱可讀取模型隱藏思維 |
| 路由插件 | 只選已設定及獲授權的連線，回傳連線參照，不持有金鑰；未裝多模型路由仍可固定模型 |
| Skill | 以 JSON 圖指定順序、資料傳遞與必要步驟；Markdown 用來說明，不代替可執行定義 |
| 管理介面 | 使用宿主服務，不直接抓取其他插件的資料表、設定檔或秘密；頁面可替換，權限不隨頁面自行改變 |
| 原生高權限插件 | 明列直接操作電腦的需求及副作用；同程序工廠及同帳戶子程序都不能稱為完整隔離 |
| MCP 轉接器 | 列舉、呼叫、錯誤與取消映射明確；MCP 連線不自帶權限或必要流程保證 |

## 給編碼 Agent 的交付約定

每次修改提交：變更目標、涉及的契約、必要權限、修改檔案、實際執行的測試及結果、未完成項目。不要把「格式檢查通過」寫成「模型或使用者流程已驗收」。不要為了通過測試而修改預期值去配合錯誤輸出。

直接沿用以上工具與契約。不另造專屬格式、不在核心加插件名稱判斷，也不靠每個插件重複塞長提示詞來保證必用。遇到缺少契約、來源不明的依賴或權限不清楚，保留草稿並詢問，不擅自安裝新環境或傳送資料。

開發工具能檢查靜態格式、路徑、部分流程及範本的實際結果。下列仍需正式宿主驗收：權限隔離、必要插件失敗時阻塞、資料真的被後續模型請求消費、更新交易、取消程序樹、舊資料搬移，以及目標電腦的安裝流程。


## 使用者看得懂的名稱與設定入口

- 插件名稱必須描述用途，例如「跨對話長期記憶插件」，不要只寫模組英文名、`service`、`provider` 或契約識別碼。說明具體效果、特色及必要條件。
- 安裝的每個插件會自動出現在這個 Agent 的設定側欄與總覽卡片；不需自行更動前端導航。不論啟用或停用都有入口，移除後入口消失。此機制按 Agent 分開。
- 有使用者可調設定時，提供 `config_schema`，以物件描述公開設定。每個欄位都要有白話 `title` 與 `description`；選擇值用 `enum`，開關用 `boolean`，數值明列上下限。宿主會產生圖形化表單，不要求使用者改 JSON。複雜或無法以表單描述的互動，請提供 `ui` HTML 設定介面。
- `ui` 在獨立框架內渲染，不能直接拿到登入憑證或 API 金鑰。設定頁開啟時，可透過下列訊息讀取自己的公開設定及請求儲存；宿主核對目前的 Agent、插件及 Schema。`config.save` 一律由宿主彈出確認視窗，不能靠插件自行傳入 `confirmed` 省略確認。取消、不合法欄位及超出範圍會回傳錯誤，不假裝儲存成功。
- 一般插件頁仍只開放已授權的 `capability.invoke`；設定讀寫訊息只有在使用者從設定入口打開時可用。每則訊息使用新的 `id`，回應沿用同一個 `id`，具有 `result` 或 `error`。`config.read` 回傳設定物件，`config.save` 成功回傳 `{saved:true}`。
- 沒有公開設定的插件也有入口，可查看用途與啟停狀態，並前往插件管理。不為了湊出設定欄位而暴露內部成長參數、金鑰或憑證。
- 既有官方模型、成長、情感、漫遊與共享插件沿用既有 GUI；這些入口只有在對應的官方插件已啟用且被目前 Agent 選用時顯示其控制項。

```javascript
// 以新的識別碼呼叫；監聽父視窗回覆中的 result 或 error。
parent.postMessage({channel:'auren-plugin-v1',id:crypto.randomUUID(),method:'config.read',params:{}},'*');
parent.postMessage({channel:'auren-plugin-v1',id:crypto.randomUUID(),method:'config.save',params:{values:{enabled:true}}},'*');
```

圖形化設定至少驗證：安裝後有入口、未登入不可用、不同 Agent 資料不混用、原值正確顯示、儲存需確認、取消不改資料、錯誤輸入被拒、重開後保留、停用明確標示、移除後入口消失。測試自訂 UI 時另確認取消、切換 Agent、離開頁面與重複請求不會繼續未核准的儲存。


## 本地權限與產品啟用的分工

新版各功能開關、進階修改模式、情緒流動及研究表演由本地登入使用者管理，不向管理端申請特殊授權。產品啟用、硬體綁定、期限及停復權仍由既有產品憑證處理；不得把功能開關當成免啟用或免到期檢查。

官方授權服務提供 local_features() 及 set_local_feature(feature, enabled, actor, confirmed)，並保留舊憑證的驗證與歷史資料。Agent 不能呼叫這些入口擴大自己的權限；必須由使用者在本地確認。原生元件程式碼修改另核對本地進階模式與對應元件的委託，仍需品質驗證。舊 capability_grant 命令不會覆寫本地選擇。第三方替換授權提供者時須保留這些服務契約，勿再新增系統強制的開發者審批門檻。


## 新功能必須有自己的內容入口

使用者查看一項功能時，應直接進入提供該功能的插件。日記在日記插件閱讀，任務在任務插件搜尋，知識與工具在知識與工具庫插件管理。請依 FORMAT.md 的 `pages` 定義內容畫面，不要求使用者到另一個全域系統頁找資料，也不要要求修改 Auren 主導航。

開發者必須：

1. 用白話命名插件、內容頁及能力；在內容頁呈現實際功能與資料，在設定頁只放公開可調選項。
2. `pages[].contract` 對應自己的出口，使用版本化 DTO／Service；不直接讀其他插件的資料庫。
3. 維持目前 Agent 的資料範圍；跨 Agent 讀寫使用既有共享授權。停用和更換提供者後不得繼續顯示舊內容。
4. 使用 `capability.invoke` 取得授權資料；不把登入憑證、API 金鑰或內部成長參數塞進 HTML。設定仲介只在使用者進入設定頁時使用。
5. 驗證安裝後出現內容入口、頁面切換、重開保存、不同 Agent 隔離、停用／替換後舊入口不再執行，以及原有搜尋、更正、封存和匯出仍可用。沒有 UI 的背景插件應如實說明，不用假數值裝成面板。

人格資料仍沿用既有建立／成長／問模式入口，不因搬進插件而開放直接改寫。


## Agent 建立與人格插件

Agent 建立介面只負責登記名字；沒有選過人格插件模式時，不應以任何模式或預設人格代填。人格插件透過 `auren.personality/1` 的 state、initialize、set_growth 介面提供四種模式；初始化只接受本地使用者明確確認，不接受 Agent 自行重設人格。既有五項人格相關契約仍可替換，整合不更動歷史記憶或人物素材。

公開模式設定與人物參數分開：使用者可以選模式、模板及成長開關，不能直接檢視或調整內部參數。需要真人素材的模仿流程沿用問答證據、來源及塑形版本檢查。


官方人格套件整合的舊路徑由 core.bundled.compatibility 轉接，舊五項 Service 契約不變。宿主只把明確選用舊官方提供者的綁定指向新套件；使用者的替代提供者、停用選擇及設定保留。轉換與原值以同一個儲存交易寫入 `plugins.personality.binding_transition`，重跑不重複遷移。

回復時先停止本地服務，還原備份中的整份舊官方目錄與舊介面，再啟動服務。宿主會按轉換紀錄回復仍等於本次轉換值的綁定；整合後使用者另行選過的提供者不會被蓋掉。人格、記憶及成長資料庫不搬移、不回復成舊副本，避免抹除新資料。舊建立與成長 API 在回復目錄時保留相容；新模式設定入口需搭配新版插件及介面。


## 有前置設定，必須先引導

任何插件只要需要使用者先選位置、輸入連線、選模式或完成初始化，就必須依 FORMAT.md 宣告 config_schema／setup，不能把必要設定藏在第一次失敗的錯誤中。安裝、啟用及進入 Agent 後，宿主會依實際設定狀態列出引導，使用者可直接進入該插件的 GUI。

請提供白話 instructions，說明要準備什麼。複雜 GUI 的設定請透過宿主的 config.save 儲存並驗證；原生初始化由 setup_status 回報實際結果，不接受使用者只按「我已完成」就放行。設定值、金鑰及內部人格參數都不得夾在準備狀態裡。

至少驗證：缺必填項目時出現引導、可直接進入設定、錯誤設定不算完成、完成後引導更新、重開後不重問、停用後移出清單、不同 Agent 獨立計算。尚未完成必要設定時不要開始模型任務；不需設定的日記等資料仍可查看。

種子問答另需全域預設模型。模式切換到種子時應先確認這項條件，缺少時在問答開始前提供模型設定入口；不能因為 Agent 有自己的模型覆寫，就假裝全域問答模型已準備好。
## Windows 原生執行補充

`brokered` Python 插件現在使用隨包 Python 3.12、AppContainer 與 Job Object，不需要使用者安裝 WSL、Docker 或啟用虛擬化。原有 stdio 協定不變，執行器會自動處理路徑及程序。

此執行器提供標準函式庫與工作目錄，不自動安裝 pip 套件、不提供網路或主機檔案存取。外部能力走平台授權；需要直接操作電腦的高信任插件仍須宣告 `native` 並取得明確同意。不要把安裝虛擬機或要求使用者修改 BIOS 寫成插件的隱藏前置條件。

工作檔名不可使用 `.auren-internal-` 前綴；這是執行器的控制通道。一般的 `request.json` 或 `stdout.txt` 可以正常作為插件自己的資料檔。

## 可選安裝與非阻塞設定引導

安裝狀態與啟用狀態不同。插件管理目錄中的 `installed=false` 套件只供瀏覽安裝，不得出現在 Agent 已安裝設定入口，不能呼叫能力或加入任務。官方可選套件由發行配置維護；第三方套件仍一律透過使用者確認安裝，不自行預裝。

`setup.blocks_tasks` 是選填布林值，預設為 `true`。像語音轉寫這類獨立手動功能可設為 `false`：宿主仍顯示首次設定引導，但未設定時只阻擋本功能，不阻塞無關的文字任務。`preparation.ready` 表示阻塞性需求都已滿足，不代表每個選填功能都設定完成；應同時查看 `items[].ready`。

需要 API 金鑰的插件不可將金鑰放入可回傳的公開 `config_schema`。請經可信宿主入口確認後加密儲存，只回傳是否已保存。語音轉寫示範在 `auren.speech`：使用者選擇音訊、確認目的服務後才轉寫，逐字稿先預覽，不自動變成聊天訊息；能力的稽核紀錄不含原始音訊、逐字稿或金鑰。

## 可供 Agent 使用的工具與本機社交範例

若能力需要由 Agent 任務呼叫，請以 `kind=tool` 匯出版本化 contract，宣告 `invoke`、完整的 input_schema 與 output_schema。宿主只會把目前已安裝、已綁定且支援 invoke 的工具列入模型可用目錄；內部 provider 與 workflow 不因此變成可任意呼叫的工具。模型提交 `plugin_call` 時只提供 contract 與 input，宿主自行附上 Agent、任務與來源身分，插件不得採信 input 自稱的作者或管理者。

`auren.social` 展示一位本機使用者與多 Agent 的私聊、群組及動態：身分來自呼叫 context、讀取與寫入皆檢查可視權限、圖片與搜尋亦走相同檢查。只有本地使用者可以查看全部內容；Agent 必須以自己的身分操作。讀取授權不能直接視為冒名發言或編輯他人內容的授權。

有 GUI 的插件仍須宣告 `ui.pages`，安裝後即有自己的內容與設定入口，不另外塞進主選單固定頁面。本機社交插件設定頁即為個人空間設定。共享資料由插件自己擁有，不能直接跨讀其他業務模組資料表。

會持續消耗模型的功能必須有可見的開始、停止與狀態。無上限漫談確實不設回合上限；已送出的模型請求可能無法立即取消，因此停止後必須丟棄晚到結果。服務重開不得自動恢復並繼續計費。所有模型提示詞須明列於 manifest 的 prompts，不能以插件身分偷偷加入固定人格。
